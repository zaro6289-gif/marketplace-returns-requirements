# 1. Требования к сервису возвратов

## 1.1. Стейкхолдеры

| Стейкхолдер | Ожидания |
|---|---|
| Покупатель | быстро и без переписки вернуть товар и деньги |
| Менеджер продукта «Возвраты» (заказчик) | сократить срок возврата денег и нагрузку на поддержку |
| Сотрудник ПВЗ | понятная процедура приёмки, минимум бумаги |
| Склад возвратов | заранее знать, что приедет, и быстро вернуть товар в продажу |
| Продавец | прозрачные причины возвратов, защита от недобросовестных возвратов |
| Финансы | контроль выплат, отсутствие двойных возвратов |
| Юристы | соответствие ЗоЗПП и 152-ФЗ |

## 1.2. Бизнес-правила

| ID | Правило |
|---|---|
| BRL-1 | Товар надлежащего качества можно вернуть в течение срока возврата по правилам площадки, но не менее 7 дней с момента получения (ст. 26.1 ЗоЗПП) |
| BRL-2 | Товары из перечня невозвратных (ПП РФ № 2463) принимаются к возврату только при браке |
| BRL-3 | Деньги возвращаются тем же способом, которым была оплата, не позднее 10 дней с даты заявки |
| BRL-4 | Если товар ПВЗ принял без замечаний, деньги возвращаются сразу после приёмки, не дожидаясь склада |
| BRL-5 | Если склад выявил следы использования у товара, по которому деньги уже вернули, открывается претензия к покупателю, а решение принимает сотрудник отдела споров |
| BRL-6 | QR-код возврата действует 7 дней. Если он не использован, заявка отменяется автоматически |

## 1.3. Функциональные требования

| ID | Требование | Приоритет |
|---|---|---|
| FR-01 | Покупатель выбирает заказ и товар и указывает причину возврата из списка | M |
| FR-02 | Для причин «брак» и «не соответствует описанию» обязательно приложить 1–5 фото | M |
| FR-03 | Система автоматически проверяет BRL-1 и BRL-2 и сразу показывает решение | M |
| FR-04 | При одобрении система формирует QR-код и список ближайших ПВЗ | M |
| FR-05 | Сотрудник ПВЗ сканирует QR и видит товар, фото из карточки и причину возврата | M |
| FR-06 | Сотрудник ПВЗ отмечает результат осмотра: «принят» или «отказ» с обязательной причиной и фото | M |
| FR-07 | После приёмки система выдаёт электронную квитанцию и инициирует возврат денег (BRL-4) | M |
| FR-08 | Покупатель видит статус возврата и получает push при каждом изменении | M |
| FR-09 | Покупатель может отменить заявку до сдачи товара в ПВЗ | S |
| FR-10 | Склад видит список ожидаемых возвратов по дням и отмечает результат проверки | S |
| FR-11 | Продавец видит отчёт по возвратам своих товаров с причинами | C |
| FR-12 | Курьерский возврат из дома | W |

## 1.4. Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-01 | Решение по заявке (FR-03) выдаётся за ≤ 3 с |
| NFR-02 | Сканирование QR в ПВЗ работает при нестабильном интернете: данные заявки кэшируются, результат отправляется при восстановлении связи |
| NFR-03 | Защита от двойного возврата: один товар из заказа — одна успешная выплата (идемпотентный ключ) |
| NFR-04 | Персональные данные и фото хранятся по 152-ФЗ, фото удаляются через 1 год после закрытия заявки |
| NFR-05 | Доступность сервиса 99,9% |

## 1.5. User stories

| ID | История | Критерии приёмки |
|---|---|---|
| US-1 | Как покупатель, я хочу оформить возврат в приложении за пару минут, чтобы не писать в поддержку | заявка оформляется не больше чем за 4 шага; решение показывается сразу |
| US-2 | Как покупатель, я хочу получить деньги сразу после сдачи товара в ПВЗ, чтобы не ждать неделями | деньги отправлены в течение 1 ч после приёмки, покупатель получил push |
| US-3 | Как сотрудник ПВЗ, я хочу принять возврат по QR-коду, чтобы не заполнять бумажные бланки | приёмка занимает ≤ 2 мин; квитанция формируется автоматически |
| US-4 | Как сотрудник ПВЗ, я хочу отказать в приёмке с фото, чтобы спор можно было разобрать | отказ невозможен без причины и фото; покупатель получает уведомление с причиной |
| US-5 | Как сотрудник склада, я хочу видеть ожидаемые возвраты, чтобы планировать смену | список на завтра доступен с 18:00 текущего дня |

## 1.6. Спецификация варианта использования «Оформить заявку на возврат»

| Поле | Описание |
|---|---|
| Актор | Покупатель |
| Предусловия | покупатель авторизован; заказ получен |
| Триггер | покупатель нажимает «Вернуть товар» в карточке заказа |
| **Основной сценарий** | 1. Система показывает товары заказа, доступные для возврата.<br>2. Покупатель выбирает товар и причину.<br>3. Покупатель прикладывает фото (если нужно для этой причины).<br>4. Система проверяет срок и категорию (BRL-1, BRL-2).<br>5. Система формирует QR-код и показывает ближайшие ПВЗ.<br>6. Система отправляет push с QR-кодом. |
| **Альтернативы** | 4а. Срок возврата истёк: система показывает отказ с пояснением и предлагает написать в поддержку, если товар бракованный.<br>4б. Товар из перечня невозвратных, причина не «брак»: отказ с пояснением. |
| **Исключения** | 3а. Фото не загрузилось: система сохраняет черновик заявки и предлагает повторить. |
| Постусловия | заявка в статусе «Ожидает сдачи в ПВЗ», QR-код действует 7 дней |
