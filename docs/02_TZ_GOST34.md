# Техническое задание на создание подсистемы «Сервис возвратов»

*Структура по ГОСТ 34.602-2020 (сокращённая, учебный кейс)*

## 1. Общие сведения

**1.1. Наименование системы:** подсистема «Сервис возвратов» (далее — СВ) платформы маркетплейса.

**1.2. Заказчик:** продуктовое направление «Возвраты». **Исполнитель:** команда разработки «Постпродажный сервис».

**1.3. Основания для разработки:** решение продуктового комитета о снижении срока возврата денежных средств.

**1.4. Плановые сроки:** начало работ — 01.11.2026, ввод в опытную эксплуатацию — 01.03.2027,
ввод в промышленную эксплуатацию — 01.05.2027.

## 2. Цели и назначение создания системы

**2.1. Назначение:** автоматизация оформления, приёмки и финансового завершения возвратов товаров
надлежащего качества и с браком через пункты выдачи заказов (ПВЗ).

**2.2. Цели:**

| Цель | Показатель | Текущее значение | Целевое значение |
|---|---|---|---|
| Ускорить возврат денег | медиана срока «заявка → деньги» | 12 дней | ≤ 3 дней |
| Снизить нагрузку на поддержку | доля обращений о возвратах | 18% | ≤ 8% |
| Автоматизировать одобрение | доля заявок, одобренных без участия сотрудника | 0% | ≥ 85% |

## 3. Характеристика объекта автоматизации

Процесс возврата включает оформление заявки, её одобрение, приёмку товара в ПВЗ, проверку на складе
возвратов и возврат денег. Сейчас заявки принимаются через поддержку и одобряются вручную, приёмка в ПВЗ
оформляется бумажным бланком, деньги возвращаются после проверки на складе.
Объём: ~40 тыс. заявок в месяц, 3 500 ПВЗ, 2 склада возвратов. Модели процесса: IDEF0 (A-0, A0), BPMN TO-BE.

## 4. Требования к системе

### 4.1. Требования к системе в целом

**4.1.1. Структура.** СВ состоит из модулей:

| Модуль | Назначение | Пользователи |
|---|---|---|
| М1 «Заявки» | оформление и автопроверка заявок, QR-коды | покупатели (мобильное приложение, сайт) |
| М2 «Приёмка ПВЗ» | сканирование QR, осмотр, квитанции | сотрудники ПВЗ (терминал ПВЗ) |
| М3 «Склад» | ожидаемые возвраты, результаты проверки | сотрудники склада |
| М4 «Выплаты» | инициирование возвратов через платёжный шлюз | автоматически |
| М5 «Отчёты» | аналитика по возвратам | продавцы, менеджеры |

**4.1.2. Интеграции:** сервис заказов (данные заказа), каталог (категории, признак «невозвратный»),
платёжный шлюз (возврат средств), сервис уведомлений (push, e-mail), терминал ПВЗ.

**4.1.3. Режимы работы:** круглосуточно; М2 работает в режиме offline-кэша при потере связи (до 4 часов).

**4.1.4. Надёжность:** доступность 99,9%; при сбое платёжного шлюза выплата ставится в очередь
с повтором каждые 15 минут, двойная выплата исключается идемпотентным ключом.

**4.1.5. Безопасность:** ролевая модель доступа (покупатель, сотрудник ПВЗ, сотрудник склада, отдел споров,
администратор); обработка персональных данных по 152-ФЗ; журналирование действий сотрудников.

**4.1.6. Эргономика:** оформление заявки не больше чем за 4 шага; приёмка в ПВЗ — не более 2 минут.

### 4.2. Требования к функциям

| Модуль | Функция | Требования |
|---|---|---|
| М1 | Создание заявки | FR-01, FR-02 |
| М1 | Автопроверка условий возврата | FR-03, BRL-1, BRL-2; время ответа ≤ 3 с |
| М1 | Выдача QR-кода | FR-04, BRL-6 |
| М1 | Отслеживание и отмена | FR-08, FR-09 |
| М2 | Приёмка по QR | FR-05, FR-06 |
| М2 | Электронная квитанция | FR-07 |
| М3 | План и проверка возвратов | FR-10, BRL-5 |
| М4 | Возврат денег | FR-07, BRL-3, BRL-4 |
| М5 | Отчёт продавцу | FR-11 |

Детальное описание требований — в документе «Требования к сервису возвратов» (01_requirements.md).

### 4.3. Требования к видам обеспечения

**Информационное:** основные сущности — заявка на возврат, позиция возврата, результат осмотра, выплата,
история статусов (см. 03_data_and_api.md). Хранение фото — объектное хранилище, срок — 1 год после закрытия заявки.

**Программное:** микросервис на платформе компании; REST API в формате JSON; события об изменении статуса
публикуются в брокер сообщений.

**Лингвистическое:** интерфейсы на русском языке; причины возврата и отказа — из справочников.

## 6. Порядок контроля и приёмки

Приёмочные испытания проводятся по программе и методике испытаний: проверяются все требования FR и NFR
с приоритетом M, сценарии use case и нагрузочный тест (40 тыс. заявок в месяц × 3 для пикового сезона).
Критерий приёмки пилота — срок «заявка → деньги» ≤ 3 дней для 80% заявок пилотных ПВЗ.

## 7. Подготовка объекта автоматизации к вводу системы

Обновить регламент приёмки возвратов в ПВЗ; обучить сотрудников ПВЗ (видеоинструкция, 15 минут);
обновить правила возврата в публичной оферте; сделать FAQ для покупателей.

## 8. Требования к документированию

Руководство пользователя для сотрудников ПВЗ и склада, спецификация API, программа и методика испытаний,
руководство администратора.

## 9. Источники разработки

Закон РФ «О защите прав потребителей» (ст. 25, 26.1); Постановление Правительства РФ № 2463
(перечень невозвратных товаров); 152-ФЗ «О персональных данных»; ГОСТ 34.602-2020;
результаты интервью со стейкхолдерами; модели процесса (IDEF0, BPMN).
